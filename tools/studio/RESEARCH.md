# Super Famicom workflow and design references

## Verified period details

- Nintendo's *Super NES Development Manual*, Book I, documents 8×8 and 16×16 background characters, per-character palette and flip attributes in the applicable modes, OBJ tables and scanline limits, and the S-DSP's BRR blocks and predictors. The PPU register appendix, especially A-2 through A-7, distinguishes OAM, VRAM and CGRAM data. Section 3, chapter 2 describes BRR. [Nintendo manual scan](https://floating.muncher.se/bot/manual/book1_text.pdf)
- Sculptured Software's 1992 development system overview describes Eon for editing background characters, larger tiles, screens and maps, including imported IFF art and author-assigned flags. It describes Rocks for sprite objects and animation sequences and Berlioz for samples, sound effects and musical scores. The brochure describes sending works in progress to a Super NES for audition and using an IBM-compatible host connected to cartridge-side development hardware. The claims establish what this vendor advertised. [Sculptured Software brochure](https://archive.org/stream/sculptured-software-super-nes-development-system-overview/ssdev_djvu.txt)

## Inference and Studio's choices

The hardware constraints and vendor brochure support a workflow that authors small reusable assets on a host, composes them into larger structures, and checks the results against the target. Practices and tools on other teams, including the intended period RPG teams, would require their own records. Studio's palette IDs, JSON metadata, file handoff, and driver-independent sequencer are modern authoring decisions.

- Tiled's layer controls and custom properties are useful precedents for independently editable layers and project-defined metadata. Studio uses ID-based references and a smaller schema for indexed SFC assets. [Tiled layer documentation](https://doc.mapeditor.org/en/stable/manual/layers/), [Tiled custom properties](https://doc.mapeditor.org/en/stable/manual/custom-properties/)
- Snes9x provides an executable reference for BRR arithmetic details such as sign extension and saturation. bsnes and Mesen's SNES tools provide cross-checks for two-page OBJ addressing, scanline behavior, rectangular OBJ flips and the distinction between presentation and memory views. Studio independently implements the format and a non-interlaced preview. [Snes9x S-DSP implementation](https://raw.githubusercontent.com/snes9xgit/snes9x/master/apu/bapu/dsp/SPC_DSP.cpp), [bsnes OBJ implementation](https://raw.githubusercontent.com/bsnes-emu/bsnes/master/bsnes/sfc/ppu-fast/object.cpp), [Mesen SNES PPU tools](https://github.com/SourMesen/Mesen2/blob/master/Core/SNES/Debugger/SnesPpuTools.cpp)
- egui/eframe supports a shared Rust UI on native and WebAssembly through a web runner and a rendering canvas. Studio only needs a native CLI and has browser-native folder access, file picking, keyboard focus, dialogs and audio. A DOM shell paired with Rust image generation through `wasm-bindgen` gives those controls native semantics and avoids a second GUI runtime dependency. [eframe web/native template](https://github.com/emilk/eframe_template), [File System Access directory picker](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)

The archival material and emulator sources are references. Studio includes its own fixture artwork, sample data and code.
